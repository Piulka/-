# Контекст для нового агента

Актуализировано: 2 ноября 2026. Проект — **Жмякее**, macOS-пульт для QA курьерского модуля Drivee. Пользователь Павел — QA, работает на Mac с Apple Silicon. Пишем ему по-русски, предельно компактно; длинные сводки и повторные подтверждения обычных правок раздражают.

## Как продолжить

1. Прочитай `AGENTS.md`, этот файл и `README.md`; посмотри `git status`, последние коммиты и реальный код нужного механизма.
2. Уточни текущую задачу из сообщения пользователя. Не начинай заново уже готовые функции.
3. Выполни правку, необходимые проверки и сборку. Сообщи коротко результат и существенные ограничения.

Это техническая передача контекста, а не копия переписки. Доступность чата, MCP-плагинов и настроек аккаунта после смены GPT-аккаунта не гарантирована. Файлы проекта и локальная конфигурация находятся на Mac независимо от подписки.

## Готовые функции и принятые решения

- Один общий интерфейс: вкладки устройств, сборок, настроек, аккаунтов, админки и редактора скриншота. Это вкладки одного окна, не дополнительные окна.
- Два Android управляются через ADB/scrcpy и показываются внутри пульта. Заголовки устройств сворачиваются.
- iPhone управляется настоящим системным «Видеоповтором iPhone» в отдельном окне. Ранее попытки встроить его приводили к скачкам курсора, активации чужого окна и миганию. Пользователь отверг этот подход. Функция связывания окон удалена; не возвращать её как работающую.
- Аккаунты разделены по test01–test10 и базовому fridi; по умолчанию test08, до 10 записей на страницу. Номер показывается открыто, префикс страны фиксирован; секреты берутся из локального vault.
- Авторизация проверяет запуск приложения, выходит из старого аккаунта, проверяет стенд, вводит выбранный номер и тестовый OTP, обрабатывает дополнительные экраны. На iOS отдельный OCR/Accessibility-флоу.
- Кнопки Android: назад, домой, недавние, force-stop текущего приложения с защитой системного интерфейса; быстрый запуск Drivee, Deeplink Checker и GeoLab.
- «Повтор ↔»: семантическое повторение нажатий/долгих нажатий и ввода между двумя Android. Нужны соответствующие экраны и однозначные элементы. Hit-test делается до исходного тапа; есть закрытие меню тапом снаружи. Не копировать просто координаты между разными разрешениями.
- Свайпы, canvas без accessibility-разметки и защищённые поля не повторяются. Разные кнопки меню в клиентском и водительском режимах пользователь отдельно просил не пытаться считать одинаковыми.
- Съёмка одного устройства или любой пары: быстрый скриншот, редактор стрелок/линий/текста/обводки, MP4 без звука, пауза и остановка. Сохранение автоматически в настроенную папку с уникальным именем; результат сразу копируется в буфер (изображение + файл для скрина, файл для видео).
- Диплинки: пресеты «Все поля» и «Адреса + цена», редактор в настройках, режимы Курьер/Город и ввод готовой ссылки. Готовая ссылка сохраняется только на время работы приложения.
- Пути диплинков: `drivee://open/client/appcity_courier` и `drivee://open/client/appcity`. Старое переключение модуля параметром `order_type_name` не возвращать.
- Для города и iPhone используются start/end-координаты двух точек. Для Android-курьера поддержан JSON-маршрут до 10 точек; поддержка конкретных полей зависит от сборки. Диплинк заполняет/открывает форму, не создаёт заказ.
- Вкладка сборок сканирует APK/IPA в Downloads или выбранной папке, показывает метаданные и ставит на выбранное устройство. APK — с сохранением данных; IPA — с существующей подписью через devicectl. Не удалять приложение автоматически при конфликте подписи.
- Логотип без фона; нажатие на него открывает устройства. Настройки сворачиваются по разделам. Имена Huawei/POCO/iPhone Air пока сознательно захардкожены, их замена записана в `CHECKLIST.md`.

## Мост Chrome: общий транспорт

Файлы `ChromeOTPBridge/` + `OTPBridge.swift`. Несмотря на историческое имя класса, этот мост обслуживает и OTP, и админку.

- Расширение Manifest V3 **«Жмякее · test08»**, версия 1.1.0; ID стабилен благодаря публичному ключу в manifest. Этот публичный ключ не является секретом.
- Доступ только к RedisInsight и `test08-podval.int.indels.dev`; нет cookies/webRequest/чтения паролей/all_urls.
- Используются уже авторизованные вкладки Chrome. Cookies/HTTP Basic не извлекаются и не передаются в пульт.
- Native Messaging host `local.zhmakee.otp`; персистентный HTTP-сервер/локальный TCP-порт не используется.
- Подготовленные файлы: `~/Library/Application Support/Жмякее/OTPBridge/extension`, host и очередь IPC рядом. Манифест native host лежит в стандартной папке NativeMessagingHosts Chrome.
- `install.py` готовит файлы; `worker.js` принимает только известные операции и выбирает разрешённую вкладку. Native host ограничивает stand, city, значения и возраст запросов; наружу выходят только коды/счётчики/разрешённые состояния.
- Запросы истекают через 5 секунд до запуска; исполнение ограничено дедлайном. Очередь и файлы приватные, запросы после чтения удаляются. При неопределённом результате нет автоматического повторения мутации.
- Изменения `admin.js`/`core.js` подхватываются при следующей инъекции после обновления файлов. Изменения worker/manifest требуют ручной перезагрузки расширения пользователем. Новые разрешения объяснить и подтвердить.
- Браузерный инструмент ранее отклонил `chrome://extensions` как недопустимый протокол. Не обходить этот отказ через native UI, CDP, команды браузера и т.п.; просить пользователя выполнить необходимое действие вручную.

## OTP — реализован и проверен

Только test08, точное Redis-подключение зафиксировано в `core.js` и проверяется по UUID и имени. В `OTPRules.swift` находятся ограничения и сообщения. Кнопка сброса рядом со входом выбранного аккаунта Android; на iPhone — в его блоке.

Проверяются только три точных имени: `auth_step_{phone}{phone}`, `auth_rdb_count:{phone}`, `rate:sms_cd_:{phone}`. Номер — тестовый префикс страны и 8 цифр. Значения Redis не читаются, по маскам ничего не удаляется. Существующие ключи удаляются ПО ОДНОМУ: пакетное DEL не работало в Redis Cluster. После удаления проверяется отсутствие ключей.

Реально воспроизведён 30-минутный лимит на test08, выполнен сброс и немедленный успешный вход на Huawei. Не расширять на другие Redis/стенды по догадке.

## Админка — реализована и проверена

Область: **test08 → Калуга, city 590 → Courier**.

- Страница: `https://test08-podval.int.indels.dev/podval/city/update?id=590#tab-custom-order-settings`.
- Поле: `OrderTypeCitySettings[door_to_door]`, значения `enabled` / `disabled`.
- `admin.js` каждый раз читает свежую форму, находит Courier и связанные ID из DOM. Не хардкодить исторические ID формы и записи настроек.
- Штатный endpoint частичного обновления: `/podval/order2020/ordertypecitysettings/update?id=...`, POST FormData с `data` (JSON только поля и order_type_city_id) и свежим `YII_CSRF_TOKEN`.
- Перед записью сравнивается ожидаемое значение, после — результат и неизменность остальных полей Courier. Конфликт требует обновить данные.
- **ВАЖНО: по последнему требованию «Сохранить» НЕ сбрасывает кэш.** Это ранний return `admin_saved` до кэш-операций. Тест проверяет отсутствие запросов GO/PHP при сохранении.
- Кэш — отдельная кнопка. GO: GET `/podval/gocache/index`, затем POST `/podval/gocache/cache` с reason и `X-CSRF-TOKEN` + `X-Requested-With`. GO использует отдельный CSRF-механизм, отличный от Yii-формы города.
- PHP: GET `/podval/stat/clearcache`, успех подтверждён текстом `Yii cache cleared`. Отдельно нажимать OK в браузере при работе через мост не требуется.
- GO подтверждает принятие запроса и сообщает задержку примерно 10 секунд; это не синхронное подтверждение фактического завершения. Не показывать ложное «всё уже применилось».
- `AdminRules.swift` валидирует результаты, `AdminView.swift` содержит вкладку. При входе на вкладку настройка читается автоматически; есть ручное обновление.
- Сейчас используется текущая сессия Chrome. Получение персонального OTP из QA API и автоматический вход в админку НЕ реализованы. Если сессия закончится, пользователь входит в Chrome.
- Пользователь объяснял источник OTP: QA API Admin, путь `/kladovka/users/search` на test08. Не читать токены/номера оттуда без необходимости; текущим функциям этот второй домен не нужен и разрешение расширению на него не выдавалось.
- Door to Door и оба кэш-механизма реально проверены на test08. Текущее значение настройки может быть изменено пользователем — перечитывать, не восстанавливать историческое значение автоматически.
- Для следующего поля пользователь может дать ссылку на вкладку + название. Изучить его фактический save-механизм и сохранить только запрошенные поля.

## Файлы, сборка и проверки

Карта основных файлов есть в README. Дополнительно:

- `AndroidRepeat.swift`, `AndroidAutomation/.../ElementMatch.java`, `TapTree.java` — повтор и семантическое сопоставление.
- `Environments.swift` и Java `StandHost` — адреса стендов. iOS базовый стенд сопоставляется с `int.indels.dev`; старые fridi-алиасы поддержаны. Не сравнивать стенд только по наличию строки test08.
- `MediaClipboard.swift` — правильное помещение изображения/файла и видео в буфер.
- `ChromeOTPBridge/admin.js`, `core.js`, `worker.js`, `native_host.py`, `install.py` — браузерная часть, область доступа и транспорт.

Команды из корня:

```sh
zsh build.sh
zsh Tests/run.sh
node Tests/otp_bridge_core_test.cjs
node Tests/admin_bridge_test.cjs
codesign --verify --deep --strict Жмякее.app
git diff --check
```

`Tests/run.sh` запускает Swift/Java/Python-проверки; JS выполняется им только если `node` доступен в PATH. На исходном Mac Node в shell PATH не был доступен; JS-тесты запускались отдельно через доступный Node REPL. Нельзя заявлять, что JS проверен, только по успешному запуску shell-скрипта без Node.

Полный набор проверок и подписанная сборка прошли для 0.12.0. Для последней 0.12.1 повторно прошли целевые Swift AdminRules, JS-проверки сохранения без кэша и отдельного сброса, сборка и проверка подписи; в запущенном интерфейсе подтверждена кнопка «Сохранить». Не менять реальные настройки повторно ради документационной правки.

После изменения кода обновить локальный unpacked extension через `python3 ChromeOTPBridge/install.py`, если менялись его файлы. Приложение перезапускать только после завершения активной авторизации/установки/записи. Не редактировать входные Swift-файлы во время компиляции.
