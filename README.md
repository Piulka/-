# Жмякее

Пульт для ручного QA мобильных приложений на Mac: два Android в одном окне и отдельный системный «Видеоповтор iPhone».

Для продолжения разработки новым агентом: [контекст проекта](PROJECT_CONTEXT.md) и [инструкции](AGENTS.md).

## Возможности

- Управление Android мышью и клавиатурой через ADB и scrcpy.
- «Повтор ↔»: двусторонние нажатия, долгие нажатия и ввод текста по элементам Android. Тап из пульта определяется по дереву интерфейса **до** нажатия: закрывающаяся кнопка не теряется после смены экрана. Бургер-меню закрывается на обоих устройствах при тапе снаружи. На другом телефоне ищется элемент по UI-ID, подписи и контексту; координаты источника не копируются. Отсутствующий или неоднозначный элемент отключает повтор. Для нажатий непосредственно на телефонах остаётся обработка accessibility-событий с ограничениями самих виджетов. Свайпы, защищённые поля и canvas без accessibility-разметки не повторяются. Кнопки «Назад / Домой / Недавние» пульта применяются к обоим устройствам. Перед авторизацией, установкой или отдельным запуском приложения повтор нужно выключить. Сессионный канал передаёт поля только в памяти, без журналирования значений.
- Переключение аккаунтов на test01–test10 и базовом fridi. По умолчанию test08; аккаунты разделены по стендам, старый каталог автоматически относится к test08.
- Быстрый запуск Drivee, Deeplink Checker и GeoLab на выбранном Android.
- Вкладка «Сборки»: APK/IPA из Downloads или выбранной папки, версии из содержимого файлов, поиск, фильтры и установка на выбранное устройство с проверкой результата. Список обновляется автоматически.
- Принудительное закрытие текущего приложения Android через `force-stop`; системный интерфейс и домашний экран защищены от этой команды.
- Режим «Ссылка»: вставка готового `drivee://…` и запуск на выбранном Android/iPhone без пересборки параметров. Вставленный текст хранится только до выхода из пульта.
- Диплинки «Курьер / Город» (`appcity_courier` / `appcity`) с общими пресетами (город получает координаты start/end для заполнения формы): выбор Android/iPhone, два готовых пресета и редактор маршрута, цены и остальных полей в настройках. Открывается форма, заказ не отправляется.
- Скриншоты одного устройства или любой пары, редактор стрелок, линий, обводки и текста. Шесть кнопок выбора и сворачиваемый блок съёмки.
- Запись MP4 без звука, пауза/продолжение и автоматическое сохранение после остановки.
- Аккаунты, настройки и разметка во вкладках общего окна. Разделы настроек сворачиваются; нажатие на логотип открывает устройства.

Пара устройств сохраняется рядом в одном файле. Папка сохранения задаётся в настройках. Скриншот (включая сохранённую разметку) автоматически копируется как изображение и файл; завершённое видео — как файл для вставки через ⌘V. Имена файлов содержат время, устройства и уникальный суффикс.

Отложенные улучшения: [CHECKLIST.md](CHECKLIST.md). Названия устройств пока оставлены прежними.

## OTP test08 через Chrome

Пароли, HTTP Basic и cookies не запрашиваются и не извлекаются. Мост использует авторизацию открытой вкладки RedisInsight в Chrome; после её окончания пользователь входит в браузере заново. Поддерживается только подключение **test08 — indelssite-redis**, указанное в рабочей инструкции.

В «Настройки → Сброс OTP · test08» подготовьте расширение. Затем в `chrome://extensions` включите режим разработчика и загрузите показанную папку `extension`. Расширение имеет доступ только к RedisInsight, админке test08-podval и к собственному Native Messaging host; разрешений cookies, webRequest, чтения паролей или всех сайтов нет. Для подключения нажмите значок расширения при открытом RedisInsight. В настройках пульта доступны проверка соединения и поиск ключей без удаления.

У выбранного аккаунта test08 рядом с входом есть «Сброс OTP»; для iPhone — одноимённая кнопка. Проверяются только три точных ключа: `auth_step_{phone}{phone}`, `auth_rdb_count:{phone}`, `rate:sms_cd_:{phone}`. Это формы, показанные на тестовом аккаунте; другие варианты ключей не угадываются. Удаляются только существующие ключи из этого набора, по одному для совместимости с Redis Cluster, после чего проверяется их отсутствие. Никаких масок удаления, Redis CLI или команд из внешнего запроса нет. При неопределённом результате автоматического повтора нет.

Запросы пульта передаются через короткоживущие файлы IPC в закрытом каталоге пользователя (0700/0600), потреблённые запросы удаляются. В ответах только коды состояния и счётчики, без значений Redis и номеров. Запросы старше пяти секунд не запускаются. Python Native Messaging host допускает только ID нашего расширения; входящие запросы ограничены test08 и форматом тестового номера. Закрытие пульта ждёт завершения операции.

На test08 проверены подключение через существующую сессию Chrome, поиск ключей, воспроизведение 30-минутного лимита, сброс и немедленный успешный вход на Android. Сброс относится к аккаунту на сервере и доступен также из блока iPhone.

Python-тесты транспорта и локальные тесты правил входят в `Tests/run.sh`. Тест браузерного исполнителя с подставным API: `node Tests/otp_bridge_core_test.cjs` (Node.js нужен только для разработки). При отсутствии Node в PATH этот тест запускается отдельно.

## Админка test08 · Калуга

Вкладка «Админка» читает настройку Door to Door для Courier города 590. Переключатель сохраняет только это поле через штатный endpoint частичного обновления. Перед записью текущее значение перечитывается: если оно изменилось с момента загрузки, запись отменяется. После сохранения проверяются результат и неизменность остальных полей Courier. Кэш сбрасывается отдельно кнопкой «Сбросить GO + PHP». Другие города, типы и стенды не поддерживаются.

«Сбросить GO + PHP» отправляет штатный AJAX-запрос GO с описанием операции и открывает endpoint очистки PHP. PHP подтверждается текстом `Yii cache cleared`; GO подтверждает принятие запроса, применение ожидается примерно через 10 секунд. При частичном или неопределённом результате пульт сообщает выполненные части и не повторяет запрос автоматически.

Используется текущая сессия открытой в Chrome админки. При истечении сессии пользователь входит в браузере и обновляет данные в пульте. Автоматическое получение OTP из QA API не реализовано; ни персональный номер, ни OTP, ни авторизационные cookies не передаются в пульт. CSRF читается из свежей страницы и используется только внутри браузера.

При обновлении с 0.11 нужно вручную перезагрузить расширение на `chrome://extensions` и разрешить добавленный доступ к `test08-podval.int.indels.dev`. Новое имя — «Жмякее · test08», ID остаётся прежним. В настройках OTP можно подготовить его файлы. Проверены чтение, выключение/включение Door to Door с возвратом исходного значения и оба сброса кэша на test08.

## Сборка

Нужны Apple Silicon, macOS 14+, Xcode с Command Line Tools и Python 3. Для Android-компонента текущий скрипт использует Android Studio JBR, SDK в `~/Library/Android/sdk`, платформу `android-37.0` и Build Tools `36.0.0`.

```sh
git clone https://github.com/Piulka/-.git zhmakee
cd zhmakee
zsh build.sh
open 'Жмякее.app'
```

При первом подключении укажите путь к ADB в настройках, подключите Android по USB и разрешите отладку. Android-компонент авторизации устанавливается при первом входе; устройство может запросить подтверждение.

`sign-local.py` использует постоянную локальную подпись Mac. Она создаётся отдельно для каждого компьютера в `~/Library/Application Support/Drivee QA Desk/Signing`. Первичная настройка доверия сертификату для подписи кода выполняется владельцем Mac. Для iPhone используются установленный Xcode и настоящее окно Apple Mirroring; доступность видеоповтора зависит от конфигурации Mac и iPhone. Авторизации iPhone нужны «Универсальный доступ» и «Запись экрана», съёмке iPhone — разрешение записи экрана.

## Локальные данные

Номера тестовых аккаунтов и общий код подтверждения находятся в приватном локальном `credentials.json` в каталоге поддержки приложения. В репозитории нет аккаунтов, токенов, ключей подписи или тестовых скриншотов. Аккаунты добавляются на вкладке пульта; общий код тестового стенда и первоначальный каталог можно передать приложению через `--seed` JSON-потоком в stdin. Поля: `name`, `role`, `phone`, `otp`, необязательные `id` и `stand` (`01`–`10` или `stage`, по умолчанию `08`). Реальные значения вводятся локально.

Подключение к рабочей инфраструктуре, VPN и доступ к тестовым сборкам настраиваются отдельно. Приложение рассчитано на тестовые сборки и известный UI; изменения экранов требуют проверки сценариев авторизации. Повторных запросов OTP при серверном лимите нет.

## Структура

- `Controller.swift` — основной интерфейс и управление устройствами.
- `Environments.swift`, `AccountCatalog.swift` — стенды и совместимый каталог аккаунтов.
- `CourierDeepLink.swift`, `DeepLinkControls.swift` — параметры диплинков, редактор пресетов и запуск на Android/iPhone.
- `BuildModels.swift`, `BuildLibrary.swift`, `BuildsView.swift`, `BuildInspector.py` — каталог и установка локальных сборок. APK устанавливается через ADB с сохранением данных и разрешённым понижением debug-версии; IPA распаковывается без изменения подписи и устанавливается через Xcode/devicectl. Удаления приложения при ошибке подписи нет.
- `EmbeddedAndroid.swift`, `AndroidWire.swift` — поток Android, декодирование и ввод.
- `AccountAutomation.swift`, `AndroidAutomation/` — авторизация Android и QA-компонент.
- `IOSAccountAction.swift` — авторизация через отдельное окно Apple Mirroring и локальный OCR.
- `MediaCapture.swift`, `ScreenshotEditor.swift` — скриншоты, MP4 и разметка.
- `Assets/` — логотипы, промпты imagegen и упаковка иконки macOS.

Сведения о стороннем scrcpy — в [THIRD_PARTY.md](THIRD_PARTY.md).

Для открытия диплинка на физическом iPhone нужен доступ к устройству через Xcode (например, USB и доверие Mac). Используется `devicectl --payload-url`; новая подпись или компонент автоматизации на iPhone не требуются. В проверенной сборке iOS JSON-маршрут игнорируется, поэтому передаются также координаты двух точек. Маршруты с промежуточными точками для iPhone отклоняются без потери адресов. Поддержка остальных полей зависит от сборки приложения. Пресеты сохраняются локально в настройках. Примеры маршрута A/B соответствуют [документации](https://docs.drivee.tech/Couriers/tech/kurerskie-deeplink).

## Проверки

```sh
zsh Tests/run.sh
```

Проверяются foreground-activity и защита лаунчера, миграция каталога аккаунтов, точное сопоставление 11 стендов на Swift/Java, валидация диплинков, кодирование кириллицы и спецсимволов, результаты установки, метаданные и безопасная распаковка IPA с сохранением содержимого подписи.

Для чтения APK нужен `aapt2` из Android SDK Build Tools; для каталога и распаковки — Python 3 (доступен с установленным Xcode). В списке показываются только APK и IPA, прочие файлы Downloads не читаются. Установка IPA использует существующую подпись сборки и её provisioning profile; пульт не переподписывает приложение.
